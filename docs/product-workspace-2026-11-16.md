# 设备工作区与 UI 调整

这一轮围绕“连接设备、检查问题、处理后复测”整理工作区。

- 主导航保留串口控制台、设备诊断、AI 助手、知识中心。日志分析和稳定性验证移入“高级工具”，已有执行历史跳转仍可使用。
- 默认保留导航文字，提供手动收起与展开，记住用户选择。控制台增加工作区标题和下一步诊断入口，统一间距、空状态与按钮层级。
- 全局设备栏只切换已打开的设备，显示连接状态文字。连接入口统一打开同一个面板，支持自定义波特率、设备名称，以及可选日志串口。连接失败保留输入并提示重试。
- 型号选择、固件资料与断开操作收进设备详情。设备组断开会同时关闭关联端口。
- 诊断使用全局当前设备，取消页面内的独立端口选择。开始运行前固定设备会话、型号和流程；确认期间切换设备会阻止启动。
- 运行中切换设备，结果和导出仍标注原目标，不能把旧结果直接用于另一台设备复测。导出内容在文件选择前生成，避免设备变化影响归属。
- 结果区直接提供 AI 分析、处理后复测、原始证据与导出。AI 分析只预填带设备标识的诊断材料，用户发送后才调用服务。
- AI 页面显示当前目标、实际附带日志数量和可用手册范围，支持展开查看即将附带的日志。
- 新手引导取消固定耗时承诺，控制台按钮真正切页；连接设备后仍可重新打开帮助。
- 移除未复核流程确认对话框的 1.2 秒自动拒绝，保留显式确认、关闭和目标变化校验。

## 验证范围

前端增加 7 项交互回归检查，总计 38 项；构建继续执行类型检查与首次加载 JS 预算。

Windows CI 在实际 Tauri/WebView2 窗口中检查深浅主题、四个主入口、高级工具入口、连接面板、导航折叠、新手引导跳转和快捷指令保存恢复。检查使用真实打包资源和真实 IPC，不连接硬件。

另一个独立的 Edge 浏览器检查使用明确的模拟 IPC 数据，覆盖自定义波特率连接、诊断失败结果、AI 草稿交接和紧凑窗口布局。截图与结果位于 `windows-desktop-smoke/product-fixtures`，仅用于交互和视觉验收，不代表真实串口或模型服务已联调。

实际桌面与模拟流程检查均通过后，CI 才上传新的 Windows 便携测试包。原有 4 项真实串口测试仍需设备完成。
