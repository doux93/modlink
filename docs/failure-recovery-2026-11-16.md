# 关闭、保存失败恢复与 AI 职责整理

## 会话关闭

关闭设备组时逐个尝试关闭原会话，成功的端口标记为已断开。任何端口失败都会保留分组和真实的部分状态，重试只处理尚未关闭的端口；全部成功后才移除记录。关闭过程中切换到其他设备不会被强制切回。

关闭请求捕获端口和连接代际，前后端均校验目标。后端在同一把锁内校验并移除会话，旧请求不能关闭同名端口的新连接；重复关闭不存在的连接视为成功。`sessionClosing.ts` 负责关闭流程，串口仓库负责保存工作区状态。

## 保存与导出

`useAsyncAction.ts` 为可重试操作提供忙碌状态、重复提交保护和错误状态。日志导出绑定打开文件对话框时的会话，快捷指令导出使用当时的数据快照。取消文件选择不会导出，写入失败保留原数据并显示局部错误。

AI 配置分为已保存状态和编辑草稿。取消会丢弃草稿；保存失败保持弹窗和输入，保存成功后才更新当前配置。API key 删除失败不会提前清除“已配置”状态。保存和删除使用同一操作锁，避免并发覆盖。

## AI 模块边界

- `useAiSettings.ts` 与 `AiSettingsDialog.vue`：配置读写、草稿和弹窗。
- `aiEvidence.ts`：日志和手册证据整理、提示词、风险及参数范围检查；不依赖 Vue 或 IPC。
- `aiTools.ts`：工具契约及不同手册模式下的工具集合。
- `Ai.vue`：会话编排、用户确认和界面协调。请求取消及代际隔离机制继续保留。

本轮将 AI 页面从 1375 行缩减到约 870 行，避免将配置、证据处理与会话编排混在一起。

## 验证

前端回归扩展为 66 项，新增部分关闭失败/重试、重复提交、重连保护、保存取消/失败/重试、导出目标快照及证据约束检查。新增 2 项无需硬件的 Rust 关闭测试。

Windows 检查补充实际 IPC 的幂等关闭、配置取消，以及模拟写入失败、部分关闭失败后的交互恢复。4 项真实串口硬件测试仍需实物设备完成；模拟检查不代替硬件验收。
