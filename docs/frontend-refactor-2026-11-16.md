# 第二轮优化：页面职责与加载开销

本轮基于第一轮修复提交 `1934c6e` 继续迭代。完整源码已经同步到
[doux93/modlink](https://github.com/doux93/modlink)，后续以仓库提交为准。

## 页面职责

- `QuickCommandPanel.vue` 负责快捷指令分组、编辑、INI 导入导出和批次控制，继续复用第一轮的设备绑定执行器。
- `TerminalLog.vue` 负责 AT 口与日志口的帧渲染、时间/Hex 格式、URC/错误码注解和自动滚动。单行注解一次计算；切换来源、恢复自动滚动或缓冲区替换旧行时均能定位最新帧。
- `AiToolCard.vue` 负责 AT/诊断确认卡片的展示和操作事件；页面仍负责设备授权、执行与模型对话。卡片组件通过事件上报勾选变化，不直接修改上层数据。
- `src/types/ai.ts` 集中 AI 卡片数据类型。控制台过滤结果也改为单次计算，供显示列表和隐藏行数共用。
- 快捷指令发送失败显示错误反馈，未连接时禁用发送；编辑按钮支持键盘焦点显示并补充可访问名称。

## 按需加载与体积

移除入口中的 UI 组件全局注册，改为每个 Vue 文件显式导入实际使用的 Naive UI 组件。
这也修复了 `NAlert`、知识中心的卡片/折叠/表格等组件此前未注册的问题。
执行历史抽屉在第一次打开时加载。

| 指标 | 第一轮版本 | 本轮版本 |
| --- | ---: | ---: |
| 入口及静态依赖 JS，压缩后未 gzip | 626.40 kB | 493.16 kB |
| 同上，gzip | 183.73 kB | 150.43 kB |
| Console.vue 行数 | 1,087 | 592 |
| Ai.vue 行数 | 1,450 | 1,345 |

入口 JS 减少约 21%，gzip 减少约 18%。这些数据衡量入口静态依赖，不代表安装包或所有页面总量。
知识中心现在会加载此前缺失的表格等组件，因此其独立页面体积增加是恢复正常渲染的一部分。

`npm run check:bundle` 遍历 Vite manifest 的完整静态依赖图，限制首次加载 JS 不超过
500,000 字节、gzip 不超过 160,000 字节。拆出一个仍立即加载的 vendor 文件不能绕过此检查；
动态页面不计入入口预算。该检查已加入 CI。

## Windows CI 与知识模块

- Python 工具使用 `tools/requirements.txt` 显式安装 PyYAML，CI 开启 UTF-8 输出。
- Windows MSVC 桌面测试通过 `MODULINK_TEST_MANIFEST=1` 嵌入 Common Controls v6 manifest，
  解决测试程序启动即报 `STATUS_ENTRYPOINT_NOT_FOUND` 的问题；正常应用构建不使用该开关。
- 完整桌面测试暴露的全文状态命名不一致已修复：后端输出 `fulltext`，与前端契约一致。
- 摘要清理改为按元数据 token 移除，保留同一行后面的 AT 命令和正文。Rust 运行时实现移至
  `modulink-core`，Python 转换工具同步修复，并共享 8 组回归数据。
- 公开索引检查继续禁止内部标记和根路径字段；源文件名检查针对标题、手册名、摘要等展示字段。
  DITAMAP 的 `owners.map_id` 是型号作用域匹配使用的稳定标识，保留其值，避免破坏知识包映射。
