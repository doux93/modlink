# 修复与优化说明 · 2026-11-16

基于 `modulink-studio-084f72b-full.7z` 的增量修复。优先处理设备会话隔离、串口响应归属和数据一致性，再拆分可测试逻辑并改善操作状态反馈。

## 1. 设备会话与串口执行

- 批量快捷指令在点击发送时固定端口、会话 generation、指令内容、循环次数与间隔；切换页签或修改快捷指令不会改变正在执行的批次。
- 相邻普通 AT 指令按最多 100 条组成后端序列，遇到失败停止；Hex 和不追加换行的原始发送仍绑定同一会话。`AT&F`、`AT^…`、`AT*…` 走 AT 执行通道。
- 原始发送 IPC 新增必需的 `sessionGeneration`，后端拒绝已经重连的旧会话。前后端必须成套更新。
- 停止按钮中断循环、等待间隔和后端任务；补上“点击停止早于后端注册任务”的竞态。已经发出的单条 AT 指令仍需等待终结响应或超时，不能撤回已发送字节。
- 超时后进入响应排空状态：旧指令迟到的终结码被消费前，不再发送下一条指令；即使序列设置为继续执行，`TIMEOUT` / `DISCONNECTED` 也会停止序列。
- 若设备始终不返回终结码，需要复位设备后重新连接。仅靠关闭再打开端口不能保证设备内部的旧任务已终止。
- 型号自动识别固定最初的会话，迟到的识别结果不会修改同名端口重连后的设备画像。
- Hex 解码先检查 ASCII 十六进制字符，再按字节对解析，避免中文、emoji 等非法输入导致 UTF-8 切片 panic。

## 2. AI 状态与界面反馈

- AI 请求开始时捕获设备、generation 和画像；切换任一上下文会使旧请求失效，并取消旧的待确认卡片。
- 新设备的模型消息历史重新开始，界面保留旧记录并显示上下文变化提示。旧设备操作结束后不会把结果追加到新设备的模型对话。
- 将请求超时/取消和工具卡片等待状态拆为 `useAiRequestGate`、`usePendingTools`；等待确认使用响应式状态，所有工具卡片完成或取消后才继续模型调用。
- 防止重复提交卡片；执行失败显示失败状态，期望正则匹配还要求终结码为 `OK`。执行中的批量操作显示绑定端口。
- 控制台滚动监听最新帧序号，修复日志达到容量上限后不再自动滚动的问题。
- 显示执行历史保存错误和快捷指令保存错误。

## 3. 持久化与架构

- 执行记录统一在后端 `ExecutionTrace` 的终结路径保存，覆盖 AT 序列、诊断、压测与场景流程。完整记录保存后，才发布裁剪后的界面事件。
- 删除前端写入执行记录的逻辑及对应 IPC，避免裁剪事件覆盖完整结果。历史加载先订阅事件，再合并查询结果；多个初始化调用共享同一任务。
- 实测能力证据改为现有 `modulink.db` 中 `json_documents` 表的事务文档，以 `BEGIN IMMEDIATE` 串行化读改写，避免多端口/多实例更新丢失。
- 首次访问时导入旧的 `capability-evidence.json`；数据库已有记录后不重复导入，原 JSON 文件保持原样。旧文件损坏时返回错误，不静默重置为空证据；执行授权在证据读取失败时拒绝放行。
- 能力证据是增量迁移，新版本后续更新以数据库为准；回退旧版不会自动把数据库中的新证据导出回旧 JSON。
- AT 参数拆分与命令校验归入 `modulink-core`，消除后端重复实现。快捷批次状态机归入 `useQuickCommandRunner`。
- 修正一个 INI fixture 的乱码文件名，与测试引用的 `NB模组测试.ini` 一致。

## 5. Windows 联调验收

1. `npm ci`，确认 rustup 能安装/选择固定的 Rust 1.94.0；运行 README 中测试和 `npm run tauri dev`。
2. 连接两个端口，在 A 上执行多轮快捷指令，切到 B 并编辑指令。确认后续仍只向 A 原会话发送；停止后不启动下一轮。
3. 用可控设备延迟一个 AT 终结码直到超时。确认下一条发送被阻止，迟到 `OK` 不会结束另一条命令；旧终结码被消费后才允许新发送。
4. 等待 AI 响应时切换端口、重连或更换画像。确认旧响应不能生成新设备可执行卡片；多个待确认卡片完成前输入保持等待状态。
5. 在执行历史中核对失败/取消状态；执行超过 50 步的任务后检查数据库完整结果，确认界面裁剪不覆盖数据库记录。
6. 让旧版生成能力证据后启动新版，检查首次导入；并行执行多个端口的能力探测，确认记录均保留。
